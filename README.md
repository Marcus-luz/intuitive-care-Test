🚀 Intuitive Care - Data Pipeline v2.0Candidato: ViniciosStack:1. Visão GeralEste projeto automatiza a extração, transformação e análise de dados de demonstrações contábeis e cadastrais da ANS (Agência Nacional de Saúde Suplementar). O sistema foi projetado seguindo princípios de Clean Architecture e KISS, garantindo modularidade e resiliência no processamento de grandes volumes de dados.2. Estrutura do ProjetoA organização do repositório separa responsabilidades de infraestrutura (Extração) das regras de negócio (Transformação):Plaintextintuitive-care-test/
├── data/                    # Diretório central de arquivos (CSVs, ZIPs)
├── backend/
│   └── core/                # Core Business Logic
│       ├── crawler.py       # Scraper para navegação e download automatizado
│       ├── processor.py     # Extração de ZIPs e normalização financeira
│       ├── enricher.py      # Cruzamento de dados (Join) e saneamento cadastral
│       ├── validators.py    # Central de validação (CNPJ e Regras de Negócio)
│       └── aggregator.py    # Motor de cálculo estatístico
└── main.py                  # Entry Point: Orquestrador do pipeline total
3. Como ExecutarPré-requisitosPython 3.10+ instalado.Bibliotecas necessárias: pandas, requests, beautifulsoup4, lxml.Passo a PassoCertifique-se de que a pasta data/ existe na raiz do projeto.Na raiz do diretório, execute o comando:Bashpython main.py
Os artefatos finais (consolidado_despesas.zip e despesas_agregadas.csv) estarão disponíveis na pasta /data.4. Análise Crítica e Justificativas (Trade-offs)EtapaDecisão TécnicaJustificativaExtração (1.1)Navegação ProgramáticaImplementado crawler que analisa dinamicamente o HTML do portal. Garante resiliência contra mudanças de nomes de arquivos ou estruturas de diretórios da ANS.Extração (1.2)Processamento em ChunksUso de chunksize=50000 no Pandas. Permite processar arquivos de milhões de linhas com baixo consumo de RAM, otimizando o uso de recursos do servidor.Validação (2.1)Filtro de CNPJ EstritoRegistros com dígitos verificadores inválidos são descartados. Prioriza a integridade para o Banco de Dados (Teste 3), eliminando ruído na fonte.Transformação (2.2)Inner Join de EnriquecimentoUtilizado how='inner' no cruzamento entre financeiro e cadastro. Registros sem match ativo são descartados por não possuírem UF ou identificação válida para análise.Análise (2.3)Saneamento de VariânciaSubstituição de NaN por 0 no Desvio Padrão. Trata matematicamente operadoras com registro único, garantindo estabilidade no relatório final.5. Resiliência e Tratamento de ErrosMapeamento de Sinônimos: O sistema utiliza um dicionário de sinônimos para identificar colunas de forma resiliente (ex: REG_ANS vs REGISTRO_OPERADORA), suportando variações históricas nos arquivos da ANS.Integridade de Caminhos: Implementada injeção de dependência de diretórios em todas as classes via main.py, garantindo que o pipeline funcione independentemente do sistema operacional ou local de chamada do script.Padronização de Tipos: Conversão explícita de identificadores (CNPJ/Registro) para String antes do Join, resolvendo conflitos entre tipos numéricos e objetos que comumente travam pipelines de dados.
